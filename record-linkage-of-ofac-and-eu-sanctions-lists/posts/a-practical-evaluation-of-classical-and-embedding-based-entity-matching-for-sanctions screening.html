Introduction

Financial institutions (FIs) must ensure that none of their customers appear on sanctions lists published by countries, international organisations, and similar bodies. Unfortunately, matching an FI's customers against lists of sanctioned individuals, organisations, companies, and so on is not straightforward: there is no common identifier that allows a direct lookup, which means this task is fundamentally a record linkage problem.

This series of posts presents the results of an evaluation of two record linkage methodologies:

  • On one hand, we evaluate what we will call the classical methodology: name cleaning and normalisation, reduction of the number of pairs to compare (blocking), and finally name comparison using a string distance metric (Jaro-Winkler, cosine similarity, etc.).
  • On the other hand, we evaluate a more recent methodology based on text embeddings of names and vector search.

The Experiment

First, it is necessary to choose two datasets to carry out the experiment described in the introduction. These datasets must satisfy two requirements:

  • Both datasets must be publicly available, and their use must not violate any personal data protection laws, confidentiality obligations, or similar regulations.
  • To evaluate the methodologies, it is necessary to know in advance which pairs correspond to the same person, company, organisation, and so on.

Taking these two constraints into account, and given that we are working in a compliance context, we have chosen to use the EU Consolidated Financial Sanctions List and the OFAC SDN List, while the ground-truth pairs have been obtained from OpenSanctions.

Evaluation Methodology

Both record linkage methodologies generate candidate pairs of records. Each pair is associated with a similarity score, and depending on whether that score is above or below a given threshold, the pair is classified as a match or a non-match. Using the ground-truth pairs provided by OpenSanctions, it is possible to compute the confusion matrix for any threshold and derive the standard indicators:

Actual Non-Match False Positive (FP) True Negative (TN)
  • Precision: the proportion of predicted pairs that are correct.
  • Recall: the proportion of true pairs that were correctly identified.
  • F1: the harmonic mean of precision and recall.

False negatives are further decomposed into two categories:

  • Structural false negatives. These are true pairs that were not detected by the record linkage methodology because they were never compared. In the classical methodology, these are pairs discarded during the blocking phase; in the embedding-based methodology, they are discarded during vector search, for example, they do not appear among the nearest neighbours.
  • Parametric false negatives. These are true pairs that were compared but not classified as matches because their similarity score fell below the chosen threshold.

This decomposition of false negatives will allow us to obtain a more complete evaluation of both methodologies.

Code and Reproducibility

All scripts used in this series are available in this public repository. The repository includes data preparation, classical matching, embedding pipelines, and shared utilities. Every result reported in this series can be reproduced directly from the code and public data sources.
